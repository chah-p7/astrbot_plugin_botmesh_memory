# BotMesh Memory

BotMesh 的分层记忆与上下文治理插件。它不替代 Persona，也不保存原始聊天全文：

- BotMesh 管理身份、人格、世界观和有向关系。
- HistoryWatch 保存可审计的原始事件，并按 BotMesh 逻辑群跨账号去重。
- BotMesh Memory 保存群级共享事实、用户纠错、按稳定人物键归属的主观记忆、情景摘要和该人物自己公开说过的话。

## 关键规则

- 身份只从 BotMesh 当前 Persona 配置动态读取。账号标签、当前自我/灵魂和身体分别处理；开启防历史覆盖后，旧聊天、昵称和模型推测不能覆盖，但管理员修改 BotMesh 配置会立即生效。
- 用户明确纠错的权威为 100，用户明确陈述为 80，Bot 回复推断为 20。低权威新内容不能覆盖高权威事实。
- 感受、态度、印象和承诺按 `memory_key` 保存。同一人物/意识换到另一个账号后仍能读取；不同键之间不会互相冒充立场。
- 回复后异步提取记忆，不阻塞当前对话。提取失败只记录日志，不影响发言。
- 同一事项的后续细节会追加到原事实、主观记忆或情景摘要；重复表述只刷新置信度和时间。
  只有明确纠正、状态变更以及当前情绪等易变信息才会覆盖。
- 原生长上下文会在请求前移除历史思考段、重复引用和旧提醒，并限制条数；不会删除 AstrBot 会话或 HistoryWatch 数据。
- 上下文按三层独立注入：结构化记忆块（`memory_context_max_chars`）、近期原始群聊块
  （`raw_history_max_chars` 独立预算，不再被记忆项挤掉）、群级滚动场景摘要块
  （`scene_summary_*`）。原始对话只覆盖最近短窗口，更长时间线由场景摘要兜底。
- 记忆项（事实/主观记忆/情景摘要）会按当前消息做关键词相关性排序后再截断，
  并限制同一人物同类主观记忆的占位数量，而不是只按权威和时间取前 N 条；查询为空时保持原有排序。
- 注入是幂等的：同一 ProviderRequest 被重试或钩子重入时不会重复附加 Memory 块；
  如果 Chathistory 已注入 `<group_chat_history>`，Memory 默认跳过自己的原始群聊副本。
- 群级场景摘要为惰性后台生成：群里有消息且摘要超过 `scene_summary_interval_minutes`
  未刷新时，下一次请求会触发后台重算，当前轮先注入已有摘要，不阻塞回复。
- 每轮请求会把当前发送者（平台账号 ID → 规范人名）以 `<current_sender>` 硬标注
  紧贴用户消息注入，并明确“以本标注为准、禁止按记忆/话题猜测发送者”，
  缓解多 Bot 账号下把 Sirin/Saya 等用户互相认错的问题。
- 事实检索与存储会按文本相似度折叠重复内容（如反复生成的“认错-纠正”事实），
  只保留权威/最新的一条，避免同类事实刷屏挤掉其他记忆。
- 维护任务按逻辑群和 `memory_key` 边界保守合并高度相似的记忆，并为各类数据执行独立 TTL。
  管理员置顶记忆以及权威度达到 80 的 active 事实不会自动过期。所有原始行都会先写入
  `memory_archive`，默认保留 365 天，可用群内管理命令恢复。

## 自动维护默认值

- 普通低权威事实 365 天；已被替代事实 90 天。
- 非置顶私有记忆 365 天；事件摘要 180 天；纠错流水 365 天。
- Memory 对话流水 30 天；滚动场景历史 30 天。
- 可恢复归档 365 天；配置为 `0` 可单独关闭任一类别的时间过期。
- 每 24 小时惰性维护一次，每批最多 1000 行；没有群聊请求时不会空转。

## 管理

管理命令：

- `/setmemorykey 蔚来`（管理员；修改当前收到命令的 Bot 在本逻辑群中的记忆身份，并写回 BotMesh Persona）
- `/memoryhub status`
- `/memoryhub facts`
- `/memoryhub add 客观事实`
- `/memoryhub correct 旧说法 => 新说法`
- /memoryhub forget fact 12
- /memoryhub clear（先预览统计）
- /memoryhub clear confirm（确认清空本群全部 Bot 记忆；执行前自动备份数据库）
- `/memoryhub maintain preview`（预览当前逻辑群会合并/过期的条目）
- `/memoryhub maintain run`（立即维护当前逻辑群）
- `/memoryhub archive 10`（查看当前逻辑群最近的可恢复归档）
- `/memoryhub restore 归档编号`（恢复一条归档记忆）

插件 Page 位于 `pages/memory-manager/`，可编辑事实、私有记忆、情景摘要和纠错记录；“日程”页签可按逻辑群查看 Dynamic Life 已写入的日程（只读）。身份统一在 BotMesh 的“群聊配置”页编辑。

管理页会以 Bot 称呼和逻辑群名称显示记忆，不再把内部 Bot ID 或 `botmesh:` 作用域当作辨认信息。选择具体群聊后可点击“立即总结”，让所选模型读取 HistoryWatch 中最近 6 小时、24 小时、3 天或 7 天的记录，生成群级情景摘要并提取明确事实与纠错；该操作不会生成任何 Bot 的私有态度。

灵魂互换场景应在 BotMesh 同一逻辑群的 Persona 中分别填写结构化身份。例如 Rev 账号可填写“自我/灵魂=蔚来、身体=莉芙、memory_key=蔚来”；TomoSpring 账号填写相反内容。换回后把 `memory_key=蔚来` 放回蔚来所在的新账号，原有主观记忆便会跟随角色恢复。也可以在相应 Bot 收到消息的群里执行 `/setmemorykey 蔚来`。Memory 不保留第二份身份副本。
